01

Executive summary

The whole architecture stays coherent because every new tool attaches to exactly one of four seams that already exist in the repo. Nothing leaks past them into the deterministic core. A seam is a stable boundary we own and exploit harder; a leaf is a swappable implementation hung off that seam. Two facts frame everything: the deployed unit is apps/web on Vercel (Neon + Inngest Cloud), and NOVA is an external voice service at api.novalabs.ae, not in-repo code. The system is paused at Human Gate 2 with 0 of 17 provider keys present and nothing ever sent, which sets the phasing more than any tool choice.

The organizing idea: four seams, everything else is a leaf

SEAM 1

One durable brain

Inngest, in packages/orchestration
Swappable leaves waitForEvent suspend throttle / concurrency per-provider step.run
SEAM 2

One Anthropic chokepoint

LlmClient (raw REST), surfaced via apps/web/lib/llm.ts
Swappable leaves streamAsk wrap model tiers canon prompt
SEAM 3

One wire format

OpenTelemetry GenAI semantic conventions, at LlmClient.complete()

SEAM 4

One master DB

Neon Postgres via Prisma
Swappable leaves pgvector (later) downstream analytics data-contract tests
FIFTH, DELIBERATELY ISOLATED BOUNDARY · EXTERNAL

NOVA voice service

Third-party / sister-team Python FastAPI + LiveKit + DSPy at api.novalabs.ae. The TS monorepo only ever touches it through nova/findings.ts and scripts/nova-call.ts. Voice vendors never reach packages/core, the scorer, or the adapter contracts, because they are not in this repo at all.
Diagram 1: the four seams (boundaries we own) versus the leaves (swappable implementations), with NOVA as a fifth, external, isolated boundary.

The four invariants every choice respects

Deterministic scoring stays in code

The LLM never emits the number. The scoring engine in packages/core is untouched. No model output, eval score, or observability score is ever fed back into it. scoring-bridge.ts maps the unified model into the scorer's ScoringSubject.

DRY_RUN default true plus a human send-gate

evaluateSendGate is pure and total: DRY_RUN and human approval are independent conditions that must both hold; gated channels add a third opt-in. We make it a durable suspend, never an LLM or MCP decision.

Vendor shapes never leak into core

The five contracts in interfaces.ts (EnrichmentProvider, SignalProvider, EmailSender, MessagingChannel, CrmStore), plus the LlmClient and the NOVA findings parser, stay the anti-corruption boundary. Every new rail is a new adapter.

Secrets only via env; UAE PDPL + TDRA for live voice

Every key is read lazily from env, on Vercel project env vars (not flyctl secrets). Compliance gates are fail-closed code.

The prune rule

All three sourced proposals converged on the same spine, which is the strongest signal it is right. Where they over-reached (agent frameworks at a zero-send stage, five overlapping eval systems, six frontend libs, eight new data rails, an analytics warehouse with no data), this synthesis prunes hard: ONE tool per job until it visibly hurts, and a cap of THREE net-new vendors per quarter.

PART 5

Enrichment and signals waterfall (the differentiator)

Effort: M-L
Current state

A real waterfall in waterfall.ts (cascade, cost ceiling, early-stop, per-field provenance in company.sources) over Clay, Apollo, Explorium, plus signals from TheirStack, PredictLeads, Exa. The SignalType enum holds hiring, funding, tech_adoption, job_change, news, web_change.

Recommended stack
NextDLD / Dubai Pulse adapter (free transaction_spike only)region-native ground truth and the strongest signal; the single biggest differentiator. ONLY the genuinely free part is buildable now.
LaterFirecrawl, Explorium-as-SignalProvider, Exa Websets, Linkup, PDL, Ocean.io, Serper, Stagehandfallbacks the existing six-rail waterfall does not need until a named live-run coverage gap appears; none is a Now item.

The DLD claim, split into free vs gated

transaction_spike is REAL and FREE, the genuine differentiator: DLD registered-transaction data is published as open data on Dubai Pulse (dld_transactions-open and dld_transactions-open-api), as bulk CSV AND an OAuth-protected REST API. It is NOT a thin wrapper: the OAuth model issues a key plus secret, exchanged at api.dubaipulse.gov.ae/oauth/client_credential/accesstoken for a token that EXPIRES (for example ~30 min), so the adapter must handle token refresh; there is a max-results limit, filter syntax, and a periodic CSV rebuild/ingest job.

off_plan_launch via Oqood / TAS is NOT openly accessible: it requires a registered, active DLD business with an Oqood developer account and formal onboarding, not an instant key. (a) PREFERRED: derive an off_plan_launch PROXY from the SAME free open datasets (a new-project first-registration spike). (b) FALLBACK: flag Oqood Gateway access as an explicit prerequisite, and until granted back the signal with Bayut / Property Finder listings or the DLD residential sale index. Do not ship code that assumes Oqood access exists.

Mandatory first task: a 1-day DLD spike

Before any adapter code, a 1-day spike confirms against official Dubai Pulse / DLD docs: dataset availability and freshness, the OAuth model and token lifetime, rate and max-result limits, and data LICENSING for commercial signal use. Gate all other DLD work on that spike passing. If the open data is not fresh enough to be a "this week" signal, or not licensable, then "transaction spike this week" is fiction and the differentiator must be re-grounded first.

How it integrates

The DLD source stays behind the existing SignalProvider contract (and, for transaction-volume firmographics, EnrichmentProvider); it never touches core or the send path. Add new SignalType values to signalTypeValues (transaction_spike, and off_plan_launch only once its source is settled) BEFORE mapping, and give them TTLs in DEFAULT_SIGNAL_TTL_DAYS. The DLD call is wrapped in its own step.run so retries do not re-bill or re-refresh. No Firecrawl, Linkup, PDL, Ocean, Serper, or Stagehand is wired now; each counts against the 3-vendors-per-quarter cap.

Visible result

A lead card showing a region-native, citation-backed reason to call now ("Developer X shows a DLD transaction spike this week"), with full per-field provenance, grounding the deterministic fit score on real DLD transaction volume rather than scraped firmographics.

PART 6

Durable runtime orchestration and the send-gate

Effort: S now, M next
Current state

Inngest is wired and serving (inngest@3.54.2 in the lockfile). waterfall.ts is one plain async loop. The approval flow passes a static approval state in the payload rather than suspending. evaluateSendGate already runs inside send-step.ts on every execution. No declarative flow control on the send step.

Recommended stack
NowStay on Inngest; make the send-gate a durable suspendstep.waitForEvent before executeSendStep; the run resumes at zero compute and evaluateSendGate re-runs on resume.
NextDeclarative throttle + concurrencychannel and mailbox caps plus quiet hours enforced on the platform, not in ad-hoc checks.
NextPer-provider step.run in the waterfalla retry memoises matched providers instead of re-billing them.
LaterTrigger.dev, Restate, Temporal, DBOS, Hatchetfuture escape hatches behind explicit triggers only; migrating now is churn, not progress.

Resolving the chokepoint contradiction: where step.ai.infer may and may not be used

step.ai.infer offloads inference through INNGEST'S OWN AI gateway, so it does NOT pass through LlmClient.complete(): it would not emit the single OTel GenAI span, not produce the CostRecord/ProviderCost row, and would split the chokepoint into two paths. Resolution: personalisation, scoring rationale, and EVERY traced or costed Claude call stays on LlmClient.complete() inside a plain step.run (the span and cost still fire; latency bills as step compute, memoised on retry). step.ai.infer is reserved ONLY for calls deliberately excluded from the OTel/cost chokepoint, of which there are currently essentially none.

How it integrates

All inside packages/orchestration, none touching the adapter boundary or the scorer. Add step.waitForEvent('await-approval', { event: 'oie/send.approved', match: 'data.actionId', timeout: '7d' }) immediately before executeSendStep in sequencing/inngest.ts; the Close Room emits that event. Attach throttle keyed by mailbox and channel and concurrency keyed by contact (Next). Keep all Inngest-shaped config only in sequencing/inngest.ts so a future engine port rewrites one file.

Visible result

The Close Room approval becomes a true durable human-in-the-loop. A regression test proves the invariant: a run that suspends, receives approval, then resumes with DRY_RUN on still returns "simulate". The most dangerous action in the system becomes the most provably controlled.

Why almost all of this is Later

A time-series moat compounds only once there IS a time series. When the analytics layer is later triggered: Neon stays the Prisma datasource, untouched in packages/db. The analytics layer is downstream, read-only, and service-isolated, behind a new read-only AnalyticsStore contract, never on the OLTP, scoring, or send path (CDC lag must never be read by the scorer). Visible result

Now: plain CI tests prove every field's provenance and freshness as data contracts, with no new tool, giving the buyer-data-room provenance story without any new infra. Later: a Metabase cockpit over real cohort data once it exists.

Top bets, ranked

Exactly six ranked bets, re-grounded against the codebase and the zero-send stage. Bet 1The durable send-gate

step.waitForEvent makes the most dangerous action the most provably controlled: approve in the Close Room, the suspended run resumes live at zero idle cost, and DRY_RUN is re-checked on resume (backed by a regression test). Bet 3The quality flywheel, starting with promptfoo

A promptfoo CI gate over the existing cases.ts turns subjective AI quality into a red/green number now. Ax/GEPA and a Langfuse judge follow later; GEPA-optimized NOVA phases live in NOVA's external repo.

Bet 4The observability spine

One OTel GenAI span at LlmClient.complete() to Sentry now (Langfuse later, when a host and live traffic exist), making cost-per-lead and regressions visible without ever feeding back into the score.

Bet 5Compliance as a provable artifact, the cheap in-repo half first

The Zod residual-PII assertion at nova/findings.ts, a phone-plus-channel Suppression schema, and a genuinely append-only Postgres AuditLog, all today. immudb, Presidio (in NOVA), Skyflow, and fail-closed external stubs follow on the TDRA-gated NOVA-go-live track.

The verify-by-conversation moat, but it is an EXTERNAL prerequisite in NOVA's own repo (LiveKit Cloud SIP, Deepgram Flux, Cartesia/ElevenLabs, Coval, behind Presidio plus fail-closed DNCR/consent), tracked in PRODUCTION-CHECKLIST and gated on TDRA approval. The flywheel with tools, and how it all fits

The same five-stage flywheel the engine already runs, with the recommended tools overlaid per stage. Every overlaid tool attaches to one of the four seams; none reaches the deterministic scorer or the send-gate decision.

Diagram 2: the flywheel with recommended tools overlaid per stage. The gold-bordered stages (Gate + Send, and the central scorer) are the invariant-protected core; the teal items are leaves hung off the four seams; the rose item is NOVA, external and isolated.

How it all fits

A lead enters the waterfall (stage 1), where the new DLD transaction_spike rail sits behind the same SignalProvider contract as every other vendor and feeds the deterministic core scorer on real transaction volume, never scraped firmographics. The scorer (stage 2, the hub) computes the number in code; promptfoo guards the rationale prose quality as a CI gate and the single OTel GenAI span at LlmClient.complete() makes cost-per-lead visible, both without ever feeding a number back in. Drafting and personalisation (stage 3) stream through streamAsk() and AI Elements into the Close Room with cited canon, prose only.

The most dangerous step, send (stage 4), is the most controlled: the Inngest waitForEvent suspend holds the run at zero compute until a human approves in the Close Room, and evaluateSendGate re-runs on resume so DRY_RUN can never be replayed away. Verification (stage 5) flows back from NOVA, the external voice service, through the findings.ts Zod boundary that rejects residual PII, into Neon, the one master DB that encodes the moat as per-field provenance and time-decayed freshness. Every overlaid tool attaches to one of the four seams, so the deterministic core, the send-gate, and the adapter contracts stay untouched while the flywheel spins faster.
