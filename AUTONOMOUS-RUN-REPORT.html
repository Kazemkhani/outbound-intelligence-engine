SECTION 2

Security and Hardening

Authentication is Auth.js v5 operator login with a bcrypt-verified password held in Fly secrets. The provider lowercases and trims the email, compares against the operator credentials in the environment, and fails closed in production: absent configuration denies all logins. Sessions are JWT only, bounded to a rolling 12-hour window that caps inactivity well below the 30-day default.

The dev fallback (dev@oie.local) is triple-gated: it requires operator credentials unset, NODE_ENV not equal to production, and ALLOW_DEV_LOGIN explicitly true. It is dead in production and tree-shaken out of the production bundle, verified by the absence of dev@oie.local from the served JavaScript.

Six response headers on every route

poweredByHeader is disabled and trustHost is baked into config, which prevents the Auth.js UntrustedHost error without depending on an environment variable.

  • Edge route-gate allowlist. Only /signin, /api/health, /api/auth, and /api/inngest are public; everything else requires a session or redirects to sign-in.
  • Liveness health check. A no-auth /api/health endpoint backs a Fly GET check that gates deploys without defeating scale-to-zero.
  • gitleaks secret-scan CI. Runs on push, pull request, and a weekly schedule, now with pull-requests read permission and GITHUB_TOKEN so it actually scans PRs.
  • Sentry observability. Caught LLM failures (rate limit, overload, empty response) are captured before re-throwing. A no-op until SENTRY_DSN is set, and it never logs the API key.
  • Secrets stay in Fly. DATABASE_URL, AUTH_SECRET, ANTHROPIC_API_KEY, and operator credentials are injected at runtime, never in the file or image. The Anthropic key is read lazily, server-only, and stayed protected.

SECTION 4

Voice and NOVA

NOVA is the operator's own production FastAPI and LiveKit agent at api.novalabs.ae, driven from scripts/nova-call.ts. It runs a four-phase arc primed by a DSPy pre-call context: Greeting (permission-based, transparent identification, never a pretext), Discovery (after-hours inbound handling, tools, monthly enquiry volume), Pitch (only on a fit), and Close (WhatsApp opt-in or follow-up time, honour opt-out immediately).

It stays in demo mode by default (demoMode is true when no NOVA key is set), so the agent only joins a LiveKit room with zero PSTN dial. It persists CallSession and CallFinding records and enriches the master database only for consented sessions: this is the verify-by-conversation moat. The loop exists because most queued numbers are toll-free or landline switchboards NOVA cannot dial, so the verify call captures a dialable mobile.

DEMO_MODEFastAPI + LiveKitDSPy pre-call4 phasesapi.novalabs.ae

Parsing of NOVA's loose payload lives in a pure, unit-tested anti-corruption layer (packages/integrations/src/nova/findings.ts). It keeps only the seven canonical finding keys (identity_confirmed, after_hours_handling, tools, monthly_volume, mobile, demo_interest, opt_in), normalises booleans to yes or no, clamps values, keeps a confidence only when it is a number in range, and never fabricates: a missing field yields no finding.

Going live is the NOVA owner's action, not a code change, and is hard-gated by UAE law. See the sign-off section below.
